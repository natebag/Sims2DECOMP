## Methodology Lesson

**Original ranking (v1) flaw:**
- Counted [no source] as "potential"
- These are NOT crackable via TU sweep workflow
- They require DOL extraction + manual reverse engineering

**v2 ranking correction:**
- Counts ONLY MISMATCH functions with source
- These can be fixed via source file edits
- Realistic for TU sweep workflow

**Critical insight:**
When tu_match.py shows "[no source]", it means:
1. No corresponding file in src/asm_decomp/
2. Cannot compile/test without creating source
3. Need to use extract_function.py first
4. Then write C++ matching DOL bytes

This is 10-50x slower than fixing existing MISMATCH files.
