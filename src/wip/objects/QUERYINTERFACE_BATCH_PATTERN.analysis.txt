## Pattern Overview

QueryInterface is a COM-style method that appears in ~19 classes across the EA codebase. All follow the same structure with only one variable: the **class-specific GUID**.

### C++ Template
```cpp
int ClassName::QueryInterface(unsigned int iid, void **output) {
    // Check if output buffer is null
    if (!output) return 0;

    // Check for universal IID or class-specific GUID
    if (iid == 1 || iid == CLASS_GUID) {
        // Load vtable
        int *vtable = *(int **)this;

        // Get method dispatch offset and function pointer
        short delta = *(short *)((char *)vtable + 16);
        void (*func)(void *, unsigned int) = (void (*)(void *, unsigned int))vtable[5];

        // Call virtual method with offset
        func((char *)this + delta, iid);

        // Set output to this
        *output = this;
        return 1;
    }

    return 0;
}
```

### Key Variables per Class
Only one piece varies: **CLASS_GUID** — the class-specific identifier.

## Assembly Pattern Breakdown

### Standard Flow:
```asm
stwu  1, -16(1)      ; prologue
stmw  30, 8(1)

mr    31, 3          ; r31 = this
mr.   30, 5          ; r30 = output pointer, update flags
beq   .L_RETURN_ZERO ; if output == NULL, return 0

cmpwi 4, 1           ; r4 = iid, check if == 1
beq   .L_MATCH       ; if iid == 1, it matches

lis   0, <upper>     ; load class-specific GUID
ori   0, 0, <lower>
cmpw  4, 0           ; compare iid with GUID
bne   .L_RETURN_ZERO ; if no match, return 0

.L_MATCH:
lwz   9, 0(31)       ; load vtable from this[0]
lha   3, 16(9)       ; load offset from vtable[16] (signed halfword)
lwz   0, 20(9)       ; load function pointer from vtable[20/5]
add   3, 31, 3       ; calculate address: this + offset
mtlr  0
blrl                 ; call virtual method

stw   31, 0(30)      ; *output = this
li    3, 1           ; return value = 1
b     .L_RETURN_OK

.L_RETURN_ZERO:
li    3, 0           ; return value = 0

.L_RETURN_OK:
lwz   0, 20(1)
mtlr  0
lmw   30, 8(1)
addi  1, 1, 16
blr
```

### Constant Fields:
- Stack frame: always 16 bytes
- Vtable offset for method info: 16 (for offset delta), 20 (for function pointer)
- Return values: 0 (no match) or 1 (match found)
- All methods are 112 bytes

## Known Gotchas

### Negative lis Values
PPC's `lis` instruction sign-extends the immediate to 32 bits.
- `lis 0, -5160` is actually `lis 0, 0xEBF8` (sign-extended from -5160)
- When calculating GUID: convert signed value to unsigned correctly
- Example: `-5160 << 16 | 51892` needs handling of sign extension

### Signed Halfword Load
The `lha` (load halfword arithmetic) instruction at offset 16 sign-extends the loaded value.
- This allows both positive and negative offsets for class members
- The offset is added to this pointer to calculate dispatch address
- Uncommon but supported pattern in EA code

### Vtable Function Pointer Index
The function pointer is always at vtable[5]:
- This is a fixed position in the QueryInterface dispatch table
- Different from other methods (Release uses vtable[29])
- Not to be confused with C++ vtable order (these are SCID-style offset tables)
